# Small Project Docs

## Purpose

These docs show how a small project can organize documentation without overbuilding. Each topic has one responsible file.

## Reading Order

1. Start here.
2. Read `api/auth-api.md` for authentication API behavior.
3. Read `frontend/login-page.md` for login page behavior.

## Folder Purpose

- `api/`: API groups, endpoints, request and response behavior, auth requirements.
- `frontend/`: UI pages, user flows, frontend state, and references to required APIs.

## Documentation Rules

- Keep one source of truth.
- Update existing docs before creating new files.
- Link to API docs instead of copying endpoint details.
- Mark incomplete work as `TODO`.
- Mark uncertain information as `UNKNOWN`.
- Keep docs short unless complexity requires more detail.
